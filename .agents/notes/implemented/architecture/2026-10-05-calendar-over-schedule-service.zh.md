# Agent Note: Calendar over the Schedule service

Status: implemented

[English](2026-10-05-calendar-over-schedule-service.md) | 中文

## Problem

人们希望有一个日历，同时展示 Harness 将运行的自动化、自己维护的普通条目，以及订阅的日历源。自动化已经作为由某个服务拥有的 Schedule 任务存在，该服务把提醒投递进会话；而这个服务是 profile 可能没有启用的官方可选 bundle。

由此产生三个决定，记录于此。

## Decision

**日历委托自动化，从不自己拥有它们。** 它通过 `ctx.schedule` 读写，因此人在日历中创建的任务与模型用 `schedule_create` 创建的任务是同一条存储记录。它同时拥有 `create`——Schedule 服务把它保留为仅宿主可用——并在调用前校验会话绑定。

**Schedule 行仍由 profile 负责。** 本 bundle 的 patch 只插入自己那一行。没有 `id` 的 patch 插入总是追加，因此在这里插入 Schedule 行会在已启用它的 profile 中挂载第二个 Schedule 服务——第二份任务存储和第二个投递定时器。因此该服务用 `ctx.get` 读取这个可选服务，而不是把它声明为注入；后者会在 profile 缺少该可选 bundle 时留下一个没有任何提示的空转插件。缺少该行时日历仍会挂载，页面仍显示本地条目与日历源，所有任务方法报告 `service-unavailable` 并指出应启用哪个 bundle。

**自动化的会话选择器与工作区可见性一致。** 只有当工作区浏览器会展示某个会话时，宿主才把它列为目标：子代理会话与用户已归档的会话都被排除，包括 live 回退本会重新加入的已加载会话。冷启动的普通会话仍可选择，因为提醒到点时由宿主 Schedule 服务自行恢复它。客户端用同一套工作区规则（空白会话中只有被主视图保留的那个）与宿主候选取交集，因此选择器在任意工作区都与侧栏一致。

**宿主无法解释的时间被拒绝，而不是被猜测。** 对无法解析的 `TZID` 和浮动日期时间，`ical.js` 都回答 `floating`，然后按进程所在时区换算，因此同一份订阅在不同机器上会把事件放在不同时间。两者都会被拒绝，提示为固定文案，不含文档内容或时区名称。全天 `VALUE=DATE` 值是源自身声明的民用日期，按原样保留，不经任何时区换算。

## 考虑过的替代方案

**由日历 bundle 插入 Schedule 行。** 未启用它的 profile 会自动获得自动化。代价是在已存在该行的 profile 中出现第二个 Schedule 服务，重复任务存储并使投递翻倍。Loader 的 patch 索引无法表达"仅在缺失时插入"，因此安全的组合与便捷的组合不能兼得。

**把 `schedule` 声明为注入并让插件等待。** 这是依赖服务的常规做法。但当 profile 缺少这个可选 bundle 时，它会产生一个没有诊断信息的空转插件，而这正是本 bundle 要避免的静默失败。

**按宿主时区解释浮动时间。** 这样能显示更多事件。但时区的选择权属于日历而非订阅方，同一事件会随运行宿主的机器而移动。拒绝则把限制说清楚，而不是把它藏起来。

## 影响

想要自动化的 profile 启用官方 Schedule bundle；不启用时日历只是本地条目与订阅源的查看器。缺少 `VTIMEZONE` 定义的订阅会被整体拒绝，而不是部分展示，因为把某个事件放在猜测出的时刻比给出一个用户可以修好的订阅更糟。拒绝时区的提示可以安全记录与展示：它不带时区名、URL、凭据或文档内容。

任务记录的是 Schedule 服务所存的状态。`lastDelivery` 回执表示提醒已进入会话收件箱，并不证明 Agent 已处理它，页面也不会为任务渲染成功或失败徽标。提醒到点时由宿主 Schedule 服务自行恢复会话，因此为未打开的会话创建的自动化在应用运行时仍会按时投递；未运行的应用在再次启动前不会投递任何内容，也不会补扫这段时间错过的发生项。

会话选择器绝不提供侧栏隐藏的谱系，因此即使某个会话已加载，自动化也不能绑定到子代理或已归档会话。宿主在会话列表返回之后才读取归档集合，因此读取期间被归档的会话不会作为目标返回。客户端保留最近一次宿主的原始候选，并在工作区归档集合变化时重新取交集，因此归档或恢复会话无需宿主重载即可更新选择器；恢复一个上一次快照遗漏的 id 会发起一次受控重取。已绑定到当前被隐藏会话的任务仍保留其存储记录并显示关联历史。

Calendar 将 `ical.js` 固定为 2.2.1。bundle 会随包分发其未修改的 MPL-2.0 许可证文本及固定版本的 npm 源码归档链接。许可门禁只接受该包名、版本和许可证的组合；其中任何一项变化都需要重新审查许可证。
